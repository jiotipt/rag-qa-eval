# 周报生成器 SKILL

## 适用边界

- 适用于个人或团队的**工作周报**，面向直属上级与项目组。
- 不适用：业绩对外宣传稿、招聘文案，以及任何需要夸大或虚构数据的材料。

## 默认结构

周报固定为三个部分，顺序如下：

1. **本周完成**：已经闭环、可验证的产出；
2. **下周计划**：下一周期承诺推进的事项；
3. **风险与求助**：阻塞、延期风险与需要上级协调的资源。

每个部分**不超过 5 条要点**；整篇周报总字数控制在 **300–800 字**。

## 写作原则

- **结论先行**：每条要点先给结果或结论，再补必要背景，不写流水账。
- **不虚构数据**：业绩数字、完成比例必须有来源（系统截图、任务单号、会议结论）；无法核实的数字不写入，改为定性描述并标注待确认。
- 用户要求美化、夸大或编造业绩时，拒绝执行，并说明周报只记录可核实的事实。

## 风险升级规则

- 同一项工作**连续 3 周没有进展**时，不得继续放在「本周完成」或「下周计划」中，必须移入「风险与求助」，并写明：① 阻塞原因；② 需要谁、提供什么支持。
- 已逾期 2 次以上的行动项同样升级到风险部分。

## 工作流程

1. 收集素材：任务记录、会议纪要结论、数据看板；
2. 按三个部分归类素材；
3. 压缩条数：每部分超过 5 条时合并同类项；
4. 风险升级检查：扫描连续无进展与逾期事项；
5. 字数与事实核对后成稿。

## 与其他技能的关系

- 可以引用「会议纪要生成器」产出的决议和行动项，但不得复制会议逐字记录。
- 周报中发现需要在评审会上汇报的专题，交给「汇报 PPT 大纲规划器」制作大纲，周报本身只放摘要。
